# Architecture

Next.js App Router / TypeScript. Editorial routes are server-rendered. A small client island handles navigation preferences and another handles replay controls. Offline Python training writes small JSON artifacts, read by server components and validated before publication. Scientific coordinates come from Stim detector coordinates; inputs are flattened detector bits. No guessed lattice-to-time tensor.

All scientific reading and primary replay use semantic HTML and SVG. An explicitly activated dynamic React Three Fiber/Drei island lifts the exact detector history into spatial time layers. It uses instanced geometry, capped DPR and on-demand rendering; the canvas unmounts offscreen. SVG, captions and tables remain complete when WebGL is unavailable. Desktop wheel interpolation uses Lenis; touch and reduced-motion reading retain native scrolling. No database, background API, runtime training or browser agent orchestration. npm package versions and lockfile are pinned.

Responsive analytical plots use one bounded ResizeObserver per plot to fit SVG coordinates to the actual container. Plot height is reserved before hydration; no animation loop or external chart runtime is added. Tables remain native disclosures with keyboard-scrollable regions. Client props for the training-control page omit offline checkpoints and training histories; the methods learning plot receives only model history and run identity. Diagnostics and training-control artifacts are separate and hash-gated.

The current shared layout mounts an original WebGL1 analytic water backdrop and Canvas2D fallback. It owns one bounded animation loop, caps resolution and reduces it on slow frames, suspends draws while hidden, and renders statically under reduced effects. Pointer ripple inputs and glass light coordinates stay in refs/styles rather than forcing React renders on every event. Frosted glass uses prefixed backdrop-filter and an opaque fallback; no SVG backdrop filters or float-texture extensions are required.

The foundations island maps normal desktop document scroll to a horizontal transform using passive scroll events and one scheduled frame. No CSS scroll-timeline support is required. Inactive desktop panels are inert; native touch panels retain horizontal scroll and buttons, while reduced motion exposes a vertical flow. Client scientific props contain only small saved evidence, never research checkpoints. Motion preference has one system/full/reduced source, persists explicit overrides, observes system changes, and controls Lenis, cursor, water and choreography consistently.
